# F-10.4B Reader → 资料库真实 Provider 验收

- 日期：2026-07-16
- Provider：DeepSeek
- 模型：`deepseek-v4-flash`
- 数据：程序生成的“旧港潮汐档案”三卷，单轮 13,297 个字符
- 隔离范围：三个专用验收项目与三个不可变 Reader Envelope
- 结论：通过

## 验收覆盖

- 每轮 3 个重叠分块，真实调用资料库专用 Provider，共执行 9 个分块请求。
- 单轮提取 6—8 张候选，覆盖人物、地点、组织、物品、事件和设定。
- `林岚/小林` 在多个分块重复出现，合并为同一候选并保留多条来源证据。
- 已有 `林岚` 卡命中更新；已有钟楼别名卡命中既有身份。
- 完整轮逐卡决定为 7 张通过、1 张放弃；放弃的既有卡摘要、正文和来源引用保持不变。
- 保存前创建正式项目备份；重复提交不重复写卡；保存后 Envelope 进入 `consumed`。
- 使用正式恢复 API 恢复后，资料库回到验收前两张原始卡。

| 轮次 | 分块 | 候选 | 结果 | 耗时 | 估算费用 |

## 安全与恢复证据

- 扫描 35 个验收项目、批次、Envelope 和指标文件：API Key 命中 0，绝对工作区路径命中 0。
- Provider Prompt 只包含当前 Envelope 分块、来源标题和已有资料卡的 ID/类型/标题/别名索引，不包含其他项目正文。
- 客户端分块大小被限制为 6,000—16,000 字符，重叠限制为 200—1,600 字符，总分块上限 40，单块候选上限 80，避免通过极小分块放大调用费用。
- 基础轮和完整轮均创建 `before-reader-compendium-application` 备份，并通过 `/api/restore-backup` 恢复成功。
- 中间失败轮的批次停留在 `review`，没有执行资料库写入，证明模型结果或测试预期失败不会留下部分应用。
