# 可选优化清单

本文件记录不影响当前版本发布、没有明确用户痛点，但在条件合适时可以改善体验、质量或可控性的需求。

这些项目默认不进入当前开发主线，也不构成发布阻塞。只有在出现明确收益证据、真实用户反馈，或实施成本足够低时，才转入 `docs/FEATURE_TODO.md` 并安排开发。

状态：`留档`、`观察中`、`建议实施`、`已转主线`、`不再考虑`。

| O-001 | DeepSeek 推理强度细分 | 留档 | 当前只有深度思考开关；开启后使用服务商默认推理强度，普通写作不受明显影响，但复杂 Agent 阶段无法确定地指定最高推理强度 | 保留主界面的开关；内部将配置扩展为 `off / auto / high / max`。普通写作默认 `high`，蓝图、大纲、复杂分析、质量审查和自动修复等阶段可按任务使用 `max`；高级设置只展示服务商实际支持的档位 | DeepSeek 的 `max` 在真实对照测试中稳定提升复杂任务质量；出现用户对质量、耗时或 token 消耗的明确反馈；或其他 Provider 也需要统一的推理强度能力层 |

## O-001 补充说明

- 截至 2026-08-13，DeepSeek V4 的有效推理强度是 `high` 和 `max`；兼容参数 `low`、`medium` 会映射为 `high`，`xhigh` 会映射为 `max`，因此不建议直接制作一个看似完整但实际存在虚假档位的 low/medium/high 下拉框。
- 当前 `enableThinking` 开关仍然有效：关闭对应非思考模式，开启对应思考模式；未指定 `reasoning_effort` 时使用服务商默认行为。
- 当前思考模式的 8000 输出额度保底用于降低思考内容占满生成额度后的截断风险，不代表推理强度，也不能替代 `reasoning_effort`。
- 若以后实施，旧配置应无损迁移：`false` 映射为 `off`，`true` 映射为 `auto`。
- 实施前应使用真实 Provider 对 `high` 与 `max` 做质量、延迟、reasoning tokens、正文完成率和截断率对照，不能只凭单次样本决定默认值。

## 维护规则

- 新条目必须说明“为什么现在不做”和“什么证据会让它升级为正式需求”。
- 不在本文件记录缺陷、安全问题、数据风险或发布阻塞；这些内容直接进入主待办的“待解决问题”。
- 条目转入主线后，在这里保留一行状态和主待办编号，详细设计与验收只在主待办维护。
- 定期清理长期没有收益证据且已被产品方向淘汰的条目，状态改为 `不再考虑`，不要静默删除决策记录。
