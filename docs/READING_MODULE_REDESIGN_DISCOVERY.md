# F-10 阅读功能改造：设计分析 0.2

- 状态：分析已收敛；正式设计与开发计划已落地，F-10.1A—F-10.1C 已完成
- 日期：2026-07-15
- 目标：把当前“本地文本预览器”升级为可沉浸阅读、可选择内容，并能把稳定内容快照安全转交给写作、资料库或半自动工作流的阅读模块。

## 1. 核心判断

本次改造包含三个分层建设的子系统：

1. **阅读呈现层**：滚动/分页、单页/双页、主题、背景、翻页方式、目录、进度、字体和快捷操作。
2. **阅读文档层**：当前项目、TXT、Markdown 和粘贴文本统一转换为带稳定章节、段落和来源定位的 Reader Document。
3. **内容转交层**：把章节或选区冻结为不可变来源快照，携带快照跳转到写作、资料库或工作流；分析、生成、审核和写入由目标模块接管。

阅读模式与编辑模式共享同一份 Reader Document 和阅读位置。这里的“编辑模式”不是新的正文编辑器，也不是分析与转交工作台，而是**选择内容并跳转到目标模块的派发模式**。阅读器不展示 Prompt、AI 结果、多卡审核或项目写入控件，避免与另外三个模块形成重复业务逻辑。

## 2. 当前实现审计

当前实现已经具备：

- 当前项目自动转换为阅读文档。
- TXT/Markdown 导入和基础章节识别。
- 章节目录、上一章/下一章、章节滚动位置恢复。
- 字号、行高、版心、段间距、字体、缩进、深色/纸张/护眼主题。
- 键盘章节切换和向下阅读。

当前结构性问题：

- 左侧导入、排版、进度、目录永久占用大块空间，正文不像沉浸阅读界面。
- 只有连续滚动；“上一章/下一章”不是页级导航，没有分页、单页/双页或翻页反馈。
- “Local Reader”文案与当前项目阅读混在一起，来源心智不清楚。
- 全书进度把每章视为相同长度，长短章混合时百分比失真；并且起始位置被强制显示为 1%。
- 外部文档正文整体保存在 `localStorage`，不适合多本书、长文档、来源版本和跨模块引用。
- 外部文档只有文件名，没有稳定 document ID、内容摘要、章节/段落 locator，也没有目标项目。
- 当前项目转换后保留 chapter ID，但聚合正文时丢失 scene ID 与段落来源，因此无法可靠把阅读选区映射回写作场景。
- TXT 固定按 UTF-8 读取，中文旧文本常见的其他编码没有识别或手动选择入口。

## 3. 信息架构

### 3.1 阅读模式

- 顶部和底部控制条默认隐藏，点击正文中部或按 `Esc` 显示。
- 左侧抽屉：书库、目录、搜索、书签、阅读历史。
- 右侧抽屉：主题、字体、字号、字距、行距、段距、页边距、对齐、阅读布局和翻页方式。
- 中央只保留书页；左右边缘负责翻页，中央区域负责显示/隐藏控制。
- 底部显示稳定位置、章节位置和可拖动进度，不把“页码”当成跨排版设置的永久标识。

建议布局选项：

- 流式滚动。
- 单页分页。
- 双页分页。
- 自动：窗口足够宽时双页，窄窗口自动单页。

建议翻页选项：

- 快速淡入淡出：默认，干扰最少。
- 水平滑动：方向感更清楚。
- 仿真翻页：可选增强效果，不作为默认；低性能设备和 `prefers-reduced-motion` 下自动降级。
- 无动画：可访问性和高频跳转选项。

成熟阅读器普遍同时提供分页与连续滚动，而不是把二者互相替代；Apple Books 还提供 Curl、Fast Fade、Scroll，以及按窗口宽度显示单页/双页。Calibre 和 Thorium 同样区分 paged/flow、单列/双列及排版设置。因此“滚动、分页、双页、翻页方式”应属于同一个布局系统，而不是分散的视觉开关。

### 3.2 编辑模式：选择与跳转

编辑模式只增加来源范围选择和目标动作，不增加分析侧栏或正文编辑器：

- 用户可选择正文选区、当前场景、当前章节、多个章节或整份文档。
- 选中文本后显示轻量上下文工具条：`去写作`、`生成资料卡`、`去半自动工作流`。
- 没有文本选区时，从范围选择器选择当前章、多章或全文，再选择目标。
- 点击动作后，阅读器冻结来源快照并立即切换到目标模块。
- 目标模块顶部显示“来自阅读器”的来源条，负责目标项目、具体意图、AI 参数、预览、审核和最终写入。

来源与目标行为：

| 来源范围 | 去写作 | 去资料库 | 去半自动工作流 |
| --- | --- | --- | --- |
| 项目场景 | 打开原场景并定位来源 | 进入资料提取流程 | 以场景快照建立工作流输入 |
| 项目章节 | 打开该章并定位首场；必要时选择场景 | 以章节快照进入提取流程 | 以章节快照进入续写、重写或分析流程 |
| 阅读选区 | 能映射时打开原场景并定位；否则作为导入草稿 | 以选区生成一张或多张卡片草稿 | 以选区快照建立工作流输入 |
| 外部 TXT/MD | 在写作模块选择新建项目或导入现有项目 | 在资料库选择目标项目并提取 | 在工作流选择目标项目和处理意图 |
| 粘贴文本 | 作为导入草稿 | 生成一张或多张资料卡草稿 | 作为临时来源快照 |

阅读器不会直接修改外部原文件。所有正式项目写入继续使用目标模块现有的确认、版本和备份规则。

## 4. 本地阅读书库与第一版格式边界

### 4.1 第一版只支持

- 当前项目正文。
- `.txt`。
- `.md`、`.markdown`。
- 直接粘贴的纯文本或 Markdown 文本。

EPUB、DOCX、PDF、书内图片、复杂 Markdown 媒体和本地字体文件导入均不进入第一版。数据契约预留 `format` 与块类型扩展点，但不提前引入解析器或固定布局阅读路径。

### 4.2 导入方式

外部 TXT/Markdown 默认复制进应用管理的本地阅读书库，而不是只保存原文件路径。原文件移动或删除不影响后续阅读和跨模块引用。

建议磁盘布局：

```text
DraftHarbor Library/reader-documents/<documentId>/
  source/<original-file-name>
  document.json
  chapters/<chapterId>.txt
  state.json
```

- `document.json` 保存标题、格式、原始文件名、编码、内容摘要、章节解析结果和导入时间。
- `chapters/` 保存标准化后的章节文本；原文件保留作为可追溯来源。
- `state.json` 保存当前稳定 locator、书签和文档级阅读设置覆盖。
- `localStorage` 只保留兼容迁移或轻量界面偏好，不再承担长篇正文权威存储。
- TXT 导入至少支持 UTF-8/UTF-8 BOM 检测与手动编码选择；中文常见编码支持作为实现时的验收项。
- 自动章节识别后提供预览与手动校正，再正式加入书库。

粘贴文本可以先建立临时 Reader Document；用户选择保留时再保存到本地书库。资料提取不要求先生成外部文件。

## 5. 内容转交契约

跨模块不传递页面 DOM 或可能继续变化的大段内存文本，而传递不可变来源快照引用：

```text
ReaderTransferEnvelope
  id / createdAt / destination
  sourceDocumentId / sourceRevisionDigest
  sourceKind: project | local-text | pasted-text
  format: project | txt | md | plain
  scope: selection | scene | chapter | chapters | document
  sourceLocators[]
  textSnapshotRef
  suggestedProjectId?
```

- 项目来源保留 `projectId/chapterId/sceneId/blockId/characterRange`，尽量映射回权威正文，不复制另一份可编辑正文。
- 本地书籍和粘贴文本引用 Reader Document 的冻结 revision、locator 与内容摘要。
- 导航状态只携带轻量 envelope ID；全文不进入路由参数或 `localStorage`。
- 目标模块解析 envelope，并校验 `sourceRevisionDigest`。
- 来源在转交后发生变化时，目标模块提示“来源已变化”，让用户刷新快照或明确继续使用旧快照；不能静默替换输入。
- envelope 是一次明确的用户转交，不建立三个模块之间的实时双向同步。

## 6. 从粘贴设定生成资料卡

现有能力可以大量复用，但流程归资料库所有。

可以复用：

- 统一 AI Task、Provider 配置、流式正文和 reasoning 气泡。
- 资料卡 schema、人物八字段、卡片保存 API、预览后确认和参考资料卡。
- 写作区“正文选区 → 单张资料卡草稿”的 Prompt 与表单。
- 工作流的分层摘要、人物/设定候选抽取、既有资料去重分类和批量建议。

需要新增：

- ReaderTransferEnvelope → 资料提取输入适配器。
- 单卡/多卡提取模式，以及卡片类型自动判断或手动限定。
- 长文本分块、逐块抽取、跨块合并、别名去重和来源证据保留。
- 与目标项目已有资料卡对比，标记“新建建议/更新建议/疑似重复”。
- 逐卡审核队列，以及外部文档来源引用。

推荐流程：

1. 用户粘贴设定或选择阅读内容，并点击“生成资料卡”。
2. 跳转资料库；在资料库选择目标项目、单卡/多卡、卡片类型和可选数量上限。
3. AI 流式提取带来源证据的候选卡。
4. 程序合并同名/别名候选，保留冲突字段，不让模型静默覆盖。
5. 与已有资料卡比较并进入逐卡审核队列。
6. 每张候选卡都必须有明确的 `通过`、`修改后通过` 或 `放弃` 决定。
7. 只有明确通过的卡片才可保存；尚有未审核卡片时，不允许“一键全部写入”。

可以提供“保存所有已审核通过项”，但这只是提交效率优化，不能绕过逐卡审核。资料库继续负责最终确认、版本校验、备份和保存，阅读器不直接写资料卡。

当前资料卡 `sourceReferences` 主要是 `sceneId + excerpt`，需要向后兼容扩展 `documentId`、`chapterId`、`blockId/range`、内容摘要和来源 revision；旧资料卡无需迁移即可继续读取。

## 7. 字体与重新分页契约

字体切换应从第一版就进入数据和分页设计，即使第一版设置界面只提供少量预设：

- 保存稳定的 `fontFamilyId`，不直接把任意 CSS 字符串写进阅读状态。
- 第一版可提供系统默认、宋体/衬线、微软雅黑/无衬线、楷体等 3—5 个带回退栈的预设。
- 系统字体不可用时自动使用回退字体，不能出现空白或不可读正文。
- 支持全局默认字体和单本文档覆盖；后者可重置为“跟随全局”。
- 字体、字号、行距、窗口宽度、单双页变化都会触发重新分页。
- 阅读位置必须锚定到章节/块/字符偏移，而不是页码；重新分页后恢复到同一文本位置。
- 高级字体管理、本地字体文件导入、可访问性字体和更细的字重选择后续完善，不阻塞第一版闭环。

## 8. 分阶段建议

### F-10.1 Reader Document 与本地书库基础

- Reader Document v2、磁盘 Store、项目场景来源映射和稳定 locator。
- TXT/Markdown 复制入库、内容摘要、编码处理、章节识别预览与校正。
- 粘贴文本临时文档与可选入库。
- 从旧 `localStorage` 文档状态兼容读取并迁移。

### F-10.2 沉浸式阅读界面

- 沉浸式控制条、书库/目录抽屉和外观抽屉。
- 流式/单页/双页/自动布局。
- 淡入淡出、滑动、仿真、无动画以及减少动态效果降级。
- 主题、背景、字体预设、键鼠/触控、全屏和真实长篇视觉验收。
- 所有排版变更后按稳定 locator 恢复位置。

### F-10.3 选择与转交闭环

- 选区、场景、章节、多章和全文范围选择。
- ReaderTransferEnvelope Store 与过期来源检测。
- 三个轻量跳转动作及目标模块来源条。
- 不在阅读器中引入 AI 分析、生成结果或正式写入界面。

### F-10.4 目标模块接入

- 写作：项目来源定位；外部内容新建项目或导入现有项目的预览确认。
- 资料库：单卡/多卡提取、分块合并、既有卡对比和逐卡审核。
- 工作流：读取冻结快照，在工作流内选择项目、模板与处理意图。
- 三条路径继续复用现有流式 AI、reasoning、备份、版本和确认机制。

### 后续独立增强

- EPUB、DOCX、PDF 和扫描/OCR。
- 书内图片、复杂 Markdown 媒体与固定版面阅读。
- 本地字体文件导入和高级无障碍字体。
- 批注、云同步和跨设备阅读进度。

这些能力必须建立在 Reader Document v2 和稳定 locator 已验收的前提下，避免为不同格式各自重建一套阅读与转交逻辑。

## 9. 已确认的设计决定

1. 编辑模式只负责选择内容和跳转，不建设分析与转交工作台。
2. 外部书籍复制进入本地阅读书库；第一版只做 TXT、Markdown 和粘贴文本。
3. 外部设定可以生成一张或多张资料卡；每张卡都必须经过用户审核。
4. 字体切换进入第一版数据与分页契约；高级字体管理可以后续完善。
5. 目标模块负责分析、生成、审核与写入，阅读器只负责稳定来源和显式转交。

以上决定消除了当前影响架构的主要歧义，可以进入正式设计与开发计划；后续视觉风格、动画强度和预设字体数量属于可迭代参数，不需要改变核心数据模型。
