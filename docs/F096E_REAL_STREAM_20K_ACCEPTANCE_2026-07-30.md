## 4. 正文规模与目标偏差

计划为 4 场、每场约 4,000 字符，计划合计约 16,000；项目目标约 20,000。实际结果：

| 场景 | 计划字符 | 实际字符 | 相对计划偏差 |
| --- | ---: | ---: | ---: |
| 斗篷内侧的黑字 | 4,000 | 6,851 | +71.3% |
| 狼牙桥上的名字交易 | 4,000 | 8,618 | +115.5% |
| 外婆屋里的第二扇门 | 4,000 | 8,122 | +103.1% |
| 红月下的契约试写 | 4,000 | 11,426 | +185.7% |

总体相对项目目标超出 75.1%，相对场景计划合计超出 118.9%。这不是输出上限截断问题，而是 Prompt 中 `targetWords` 只形成了弱提示。根据用户 2026-07-30 的最终决定：

1. 目标字数继续作为大致规模提示、进度参考和诊断信息，不改成硬截断或硬预算区间。
2. 保存计划/实际偏差，但不能仅因超出目标阻断、自动重写或截断正文。
3. 只在偏差同时造成场景职责越界、节奏失衡或质量下降时，通过对应质量锁处理真正的问题。
4. 到达目标附近时优先保证完整场景、自然收束和文章质量；用户仍可继续生成。

## 5. 正文质量检查

### 5.1 已通过

- 没有出现 `场景 6-1`、批次编号、`fineOutline`、`targetWords`、Prompt、JSON 或 Markdown 标题等过程信息泄漏。
- 四个场景标题和四个独立 Revision 正确保存。
- 第一场结尾自然停在狼提出“要名字”，第二场从同一谈判现场承接；第二到第三、第三到第四也没有重新初始化人物状态。
- 小红帽在第二场明确拒绝狼的初始条件，主动设计限期借名反约，并利用交易继续索取情报；“主动与狼交易”的内容要求实际已经完成。
- 红斗篷记录谎言的规则经过多次可验证运用，母亲、外婆和猎人教团的因果链开始形成。
- 主题词出现稳定：红斗篷 67 次，名字/乳名/称呼 141 次，谎言/撒谎 20 次，主动选择相关词 18 次。

### 5.2 需要修复

1. **场景职责漂移。** 第三场计划结果是“打开隐藏门并看到母亲仍活着的证据”，但正文结束在洛塔要求开门；真正开门和证据揭示被推迟到第四场，导致第四场同时承担第三场结尾和自身契约高潮。
2. **对话比例不足。** 实际约 19.31%，低于用户指令的 25%–35%；第四场尤其依赖规则解释和内心推演。
3. **技术说明腔仍然出现。** 第四场出现“契约的自动生成约束系统检测到了一个它无法归类的操作”等表达，与黑童话叙述不协调，说明现有“避免技术说明腔”只进入 Prompt 还不够，需要可检测指标。
4. **规则文本重复。** 确定性检查找到三处重复短句，其中两处是契约条款和斗篷温度反应在同一场重复。部分重复属于有意回引，但第四场的解释密度确实过高。
5. **确定性方向检查存在误报。** 它因为没有逐字找到完整约束句而报告 `direction_missing`，但第二场已经明确发生主动交易。该检查只能作为提示，必须结合场景计划或语义审查，不能升级为硬门禁。
6. **usage 缺失。** 本次真实流返回没有提供可保存的 usage，四次调用的 token 与成本均为 0；需要检查 DeepSeek 当前流式响应是否返回 usage，或增加不暴露密钥的本地 token 估算。

## 6. 运行中修复

真实截图发现正文舞台已经显示 208 字符时，下方旧“本步进度”仍显示 1 字符。原因是旧面板每约 500 字才刷新一次，而新舞台按动画帧刷新。

现已修复为：

- 流式舞台每累计约 50 个新字符同步一次紧凑进度面板。
- 第一批字符立即同步。
- 浏览器回归断言两个区域报告相同的已接收长度。

该修复发生在真实运行完成后，因此保留截图仍能作为旧读数滞后的复现证据。
