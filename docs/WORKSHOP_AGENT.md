# 讨论中的项目助手

打开作品，进入「讨论」，创建或选择对话，再切换到「项目助手」。助手使用设置中的当前模型；普通讨论仍保留。

可尝试：

- 「阅读当前场景，核对沈砚的人物动机，提出修改建议。」
- 「查找有关铜钥匙的正文和资料，检查是否矛盾。」
- 「把本场已经明确的人物信息整理为资料卡，未知信息不要补写。」

助手可以检索、阅读当前作品中的场景正文、摘要和资料卡，拟定正文／摘要修改，以及新增或更新资料卡。它不提供删除、跨项目、任意文件、命令执行或浏览网页工具。

修改先出现在对话的预览中。更新只展示变化字段，新增资料展示有效字段；点击「确认应用」后才写入。应用前自动生成备份，并检查目标是否仍是阅读时的版本。如果目标被改过，整批建议会被拒绝，需要重新提问。

「撤销此次修改」仅在相关内容仍保持应用后的版本时可用，保留其他场景和资料卡的后续编辑。待确认建议可取消；运行中的任务可停止。停止会中止本地请求并隔离迟到结果，远端是否已经停止处理取决于模型服务。

使用助手前需保存正文和资料卡中的输入。助手写入或撤销后，编辑区、资料库与阅读器会刷新为最新内容。普通正文保存不会再覆盖独立保存的资料卡、提示词和讨论记录。

## 首版限制

- 每次任务最多 12 个工具步骤、10 项改动、3 分钟。单条记录完整阅读上限为 32,000 字符；超过限制会提示缩小范围，不允许基于截断正文覆盖整个场景。
- 任务操作状态保存在当前应用进程中，结束后约 30 分钟过期，也可能在较多新任务产生时被清理。重启或过期后，历史预览可查看，但不能继续应用或快捷撤销；需要重新提问，或使用「恢复」中的备份。
- 应用过程异常会尝试整批回滚。若进程中断留下未完成写入记录，系统会拒绝重复应用，需使用备份恢复并核对内容。
- 范围控制由业务接口与项目路径校验实现；这是应用内权限边界，不是操作系统沙箱。链接到其他位置的项目或内容文件不支持助手操作。

## 开发验证

`npm run workshop-agent-test` 检查受限读取、工具循环、预览／写入／撤销和版本冲突。`npm run workshop-experience-test` 检查普通讨论与助手界面，并通过本地模拟模型的真实 HTTP 流完成一次正文与资料卡修改、撤销及后续保存。

可运行 `node tests/workshop-agent-fixture.js` 打开临时演示环境。该环境使用模拟模型和临时作品，不调用真实 API，也不修改日常使用的数据目录。
