## 观察到的结构

当前写作页是三栏布局：左侧目录、中央纸张编辑器、右侧 Copilot。实现已经具备隐藏目录、隐藏辅助、专注模式、辅助栏右/下切换和侧栏拖拽宽度等能力，因此问题不是缺少布局能力，而是大量操作同时暴露。

在 1280 × 720 下实测：

- 三栏宽度约为 238px / 624px / 340px；编辑器是最重要的区域，却只占约一半宽度。
- Copilot 有 8 个一级页签：AI、改写、人物、资料、元数据、结构、查找、历史。
- AI 页内容高度约 1086px，可视高度约 595px；建议、提示词模板、生成输入、写入位置、模型设置被拆在同一条长滚动流中。
- 编辑器顶部存在 16 个按钮节点（其中部分按状态隐藏），可见操作仍包括专注、保存、朗读、符号、排版、避用、目录/辅助切换、位置切换以及跨模块发送。

## 主要问题（按优先级）

### P1：写作主路径被工具栏和第三栏分走

用户进入写作页的第一任务是“选场景并写正文”，但首屏同时展示目录操作、编辑工具、布局切换和 Copilot 入口。视觉中心仍然是编辑器，但交互中心被分散成三处。

### P1：Copilot 的一级分类过多，且不同性质混在同一层

AI/改写是当前动作，人物/资料是上下文，元数据/结构是文档管理，查找/历史是维护能力。它们被放在同一个 8 项 tab 条里，导致用户要先理解产品分类，才能开始写作。

### P1：AI 面板把“立即动作”和“高级设置”串成一条长表单

续写、按节拍、总结、建议、提示词模板、全局前缀、输入、写入位置、模型设置都在同一滚动容器中。高频动作和低频配置没有层级，且生成按钮在滚动后才出现。

### P2：编辑器顶部动作没有按频率分组

保存、专注是高频；朗读、符号、排版、避用是辅助工具；目录/辅助/位置是布局控制；发送到讨论/保存为资料是跨模块动作。现在都占据同一条横向工具区。

### P2：空状态与编辑状态的布局没有明显模式切换

没有项目时仍保留完整的 Copilot 和编辑工具框架，用户能看到很多“暂时不能用”的能力；这会放大初次进入时的复杂感。

### P1：生成结果不能使用透明浮层

生成结果目前位于编辑器正文区域上方的绝对定位浮层中，并且样式允许使用带透明度的背景。正文文字一旦滚动到结果卡片下方，就会和结果内容叠在一起，尤其是长段落和浅色纸张主题下很难分辨。

这部分需要作为硬性可读性要求处理：

- 结果容器使用完全不透明的主题面板背景，禁止 `transparent`、低透明度 `rgba` 或透背景滤镜。
- 结果卡片必须有明确的边框、阴影和标题层级，和正文形成独立阅读层。
- 结果出现时给正文预留与结果卡片实际高度相匹配的底部空间，不能只依赖固定的 `padding-bottom`。
- 结果操作区固定在结果卡片底部，`保留 / 重试 / 撤回` 始终可见。
- 流式生成期间只显示“正在生成”的不透明状态卡；生成完成后再切换为可滚动结果内容。

## 建议的 v1 信息架构

目标是保留现有数据绑定和功能，只调整信息层级。

```text
写作工作区
├─ 顶部：场景名 + 保存状态 + 字数
│  └─ 更多（朗读 / 符号 / 排版 / 避用 / 导出）
├─ 左栏：目录（章节、场景、新建）
├─ 中栏：正文编辑器（唯一主视觉）
└─ 右侧抽屉：按当前任务切换
   ├─ 写作（默认）：续写 / 节拍 / 总结 / 改写
   ├─ 上下文：人物 / 资料 / 场景引用
   └─ 文档：元数据 / 结构 / 查找 / 历史
```

### 具体落地方式

1. 把右侧 8 个 tab 收敛成 3 个入口：`写作`、`上下文`、`文档`。原有 8 个面板保留，改为二级 tab 或面板内折叠分组。
2. `写作`面板首屏只保留三件事：动作卡（续写/节拍/总结/改写）、一句方向输入、生成按钮。提示词模板、写入位置、模型设置、全局前缀全部收进“高级设置”。
3. `上下文`面板集中人物、资料、章节/场景引用；默认显示当前上下文摘要，只有用户主动展开时才列出引用项。
4. `文档`面板集中摘要、标签、POV、时态、结构操作、查找与历史，避免把维护功能和 AI 动作混在一起。
5. 编辑器顶部只保留 `专注`、`保存`、`更多` 和状态信息；朗读、符号、排版、避用、布局切换和跨模块发送移入“更多”菜单。保留现有快捷入口和 data 属性，先做视觉收纳。
6. 左栏默认保持目录，但项目头部压缩为项目名 + 章节/场景计数；“新场景/新章节”放入一个 `+` 菜单，减少两个大按钮长期占位。
7. 没有项目或没有场景时，右侧改为单一引导卡，只显示下一步（打开书库 / 新建作品）；完整 Copilot 面板在选中场景后再出现。
8. 生成结果使用不透明的独立确认卡，和正文分层显示；必要时把确认卡放入编辑器底部的文档流，而不是覆盖正文。
9. 保留当前的专注模式、侧栏折叠、辅助栏右/下切换和拖拽宽度能力；v1 不改数据结构、不改 AI 请求协议。

## 推荐实施顺序

### 第一版（低风险、先验证观感）

- 只做 CSS/HTML 分组和默认收起状态。
- 右侧改成 3 个一级入口，原面板通过二级分组访问。
- 工具栏收进“更多”菜单。
- 空状态使用单一引导卡。

### 第二版（交互优化）

- 根据选区/当前场景自动切换写作与改写上下文。
- 生成前把“方向、上下文、写入位置、模型”显示成一张可确认摘要。
- 把生成结果固定在编辑器底部的确认条，避免用户在右栏滚动寻找结果。

### 第三版（个性化）

- 保存用户偏好的栏宽、默认面板和助手位置。
- 支持专注模式下只保留正文和最小状态条。

## 交互验收清单

- 进入已有场景后，首屏能看到场景名、正文、保存状态和一个明确的 AI 下一步。
- 续写路径不需要滚动才能看到输入和生成按钮。
- 低频设置仍可访问，但不会与高频写作动作竞争首屏。
- 目录、正文、助手任一栏隐藏后，正文宽度明显增加且不丢失当前状态。
- 键盘焦点、ARIA 标签和现有 `data-native-*` 绑定保持不变。
- 空状态不展示大段禁用控件，只显示下一步引导。

## 审计结论

这部分非常适合沿用工作流页的思路，但不建议简单把写作表单“搬到更宽的地方”。写作页的最佳方向是“正文优先 + 任务型助手 + 按需打开的文档工具”：先减少一级决策，再利用现有折叠/抽屉能力承载完整功能。建议先做第一版信息分层，完成后再用同一组截图做视觉回归。

## v3 实现结果（2K 适配与底部高度调整）

- 底部助手不再按视口高度无限放大：大屏默认高度限制在约 400–560px，2K 下正文编辑区仍保留约 780px 高度。
- 底部助手顶部增加水平拖拽分隔条，可上下拖动调整高度；双击恢复默认高度，用户设置保存到本地偏好。
- 拖拽高度有上下限，避免助手吞掉正文区域，也避免低分辨率下完全看不到生成输入。
- 分隔条会根据当前布局更新为水平/垂直方向和辅助标签，右侧模式仍保留原有宽度拖拽。

2K 实测（2560 × 1440）：默认网格约为 `正文 836px / 助手 560px`，正文编辑体约 `782px`；助手内容无横向或纵向溢出。拖动后可扩展到 `720px`，正文仍保留 `676px`。

## v4 实现结果（底部写作画布模式）

本轮根据“底部助手时正文显示区域也应随布局变化”的反馈，加入底部专用的正文画布规则：

- 右侧助手继续使用相对窄的阅读纸张；底部助手切换为最多 `1280px` 的宽写作画布，减少 2K 屏幕两侧的大块空白。
- 底部模式缩小标题和页脚留白，把更多垂直空间交给正文；短窗口（高度不超过 820px）进一步压缩纸张标题区，同时保留场景语义和页脚状态。
- 目录树和场景标题增加最小宽度约束并关闭横向溢出，长标题只截断显示，不再在工作区底部产生横向滚动条。

## v5 实现结果（右侧助手拖拽与生成结果可读性）

- 修复右侧助手宽度不随拖拽变化的问题：最终布局级联现在使用 `--native-assistant-width`，拖动结果会保存到本地偏好；最小助手宽度为 `320px`。
- 右侧生成输入框设置 `220px` 最小宽度并使用 `width: 100%`，助手变宽时输入框同步变长，缩小时不会压缩到不可用。
- 生成结果确认卡改为深色完全不透明阅读层（深色底、浅色正文、独立边框和操作区），不再依赖主题半透明变量与正文纸张混合。
- 右侧拖拽手柄增加常态可见的抓取线，仍保留悬停高亮和双击恢复默认宽度。

v5 验证：右侧助手拖拽、宽度持久化和输入框联动已纳入 `writer-button-audit`；三套主题的生成结果卡均实测为不透明高对比配色，`npm test` 全部通过。

## v6 实现结果（底部生成结果流式布局）

- 底部助手模式下，生成结果卡不再使用正文区域的绝对定位浮层，而是进入正文网格的独立行。
- 正文、结果卡、纸张页脚按顺序排列；结果卡不会覆盖正文或页脚，预览和续写内联确认两种状态都适用。
- 1280×720 短窗口额外压缩结果卡和标题区，仍保留结果正文、确认按钮和可用的正文区域。

复测结果：`1920×1080` 下预览卡与页脚无重叠，内联确认卡与页脚无重叠；`1280×720` 下页面无横向溢出，预览状态正文区域仍保留约 `64px` 高度。相关回归已加入 `writer-button-audit`。

## v7 实现结果（2K 底部助手默认高度）

- 2K 大屏下底部助手默认高度由最高 `560px` 调整为约 `420–440px`，仍能完整展示当前写作栏目的内容，同时把约 `120–140px` 还给正文。
- 助手继续贴住窗口底部；用户已经通过拖拽保存的高度偏好不受影响，只有没有保存偏好时使用新的默认值。
- `2560×1440` 实测默认助手约 `432px`，生成区内容可完整显示，正文编辑区由约 `836px` 增加到约 `964px`。

## v8 实现结果（正文生成确认条与安全拖拽）

根据真实生成流程的复测，修正了 v6 中“把确认卡放进正文网格行”的策略：它会挤出正文并在用户截图中遮挡一大块内容。现在确认区恢复为编辑器内的紧凑浮条，但默认优先落在正文右侧空白区，空间不足时才贴到正文边缘。

- 续写内容仍统一写入正文，但光标保持在新增内容末尾，不再把整段文字设为选中态；浅色纸张上不会再出现“浅色选中底 + 浅色字体”的不可读效果。
- 确认条使用深色不透明底，默认宽度约 `320px`，只保留状态说明和“保留 / 重试 / 撤回”三个小按钮；预览任务仍可显示结果正文。
- 确认条可通过“拖动”手柄自由移动，位置会保存到本地；拖动始终限制在编辑器正文区域内，窗口尺寸变化时自动重新夹紧，双击手柄可恢复默认位置，避免被拖出后无法找回。
- 正文不再为确认条预留大块底部空白，页脚也不再被确认条覆盖；确认条作为独立深色层与正文保持清晰分层。

v8 回归覆盖：真实续写后 `selectionStart === selectionEnd`、确认条边界夹紧、拖拽位置持久化和双击复位；`writer-button-audit`、`writer-layout-audit`、`writer-realistic-visual-audit` 与 `npm test` 均通过。

## v9 实现结果（待确认正文标记与正式提交）

- 在正文 `textarea` 上增加同步镜像层，只对尚未确认的生成片段显示背景和左侧标记；原生选区不再承担“区分新旧内容”的职责。
- 镜像层跟随正文字体、字号、行距、内边距和滚动位置变化，点击正文其他位置后标记仍然保留。
- “保留”会先校验正文没有被用户改动，再把当前生成结果写入 `snapshot.sceneContents`，刷新正文统计并清除镜像层；确认后内容完全恢复为普通正文样式。
- 如果用户在待确认期间修改了正文，镜像标记会隐藏，确认操作会被阻止并提示重新生成或撤回，避免覆盖用户修改。
