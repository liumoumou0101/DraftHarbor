# F-10.2E Reader 最终体验验收

- 日期：2026-07-16
- 环境：Windows 11，Node v24.11.1，win32-x64，本地临时目录
- 数据夹具：1,000,311 个 UTF-16 字符、100 章、1,000 个正文块
- 视觉夹具：4 章，覆盖长章、短章、对话、代码文本和中英混排

## 自动化结果

| 验收项 | 结果 | 证据 |
| --- | --- | --- |
| 键盘与无障碍 | 通过 | 抽屉 `inert`、焦点环绕、标签 Home/End/方向键、焦点恢复、状态 `aria-live` 均由 `reader-shell-test` 覆盖 |
| 缩放与窗口布局 | 通过 | 1280×800 的 100%/125%/150%/200% 等效视口，以及 1366×768、1920×1080 均无横向溢出、不可达控件或抽屉越界 |
| 真实长篇视觉 | 通过 | 深色双页、纸张单页、护眼流式和窄屏自动布局均无页面裁切；正文对比度为 11.81–13.90 |
| 长章 DOM 上限 | 通过 | 流式阅读窗口不超过 73 个正文块；分页只渲染当前一页或两页 |
| 远程资源门禁 | 通过 | 四个真实视觉场景没有远程请求 |

布局截图保存在 `.ai_state/test_reports/reader_layout_audit`，真实长篇截图保存在 `.ai_state/test_reports/reader_realistic_visual_audit`。低高度视口会从分页安全降级为流式布局，保留同一 Reader Locator，不覆盖用户保存的自动布局选择。

## 百万字符性能结果

先预热 1 次，再测量 5 次；报告中位数和 p95。搜索与分页直接使用完整 1,000 块、约百万字符章节，没有缩小夹具。

| 操作 | 中位数 | p95 | p95 预算 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 文件解析与导入预览 | 28.91 ms | 40.36 ms | 8,000 ms | 通过 |
| 原子确认入库 | 383.36 ms | 404.54 ms | 7,000 ms | 通过 |
| 单章按需读取 | 1.88 ms | 1.95 ms | 1,200 ms | 通过 |
| 完整百万字符字面搜索 | 3.80 ms | 6.52 ms | 1,500 ms | 通过 |
| 完整百万字符临时分页 | 1.45 ms | 2.25 ms | 1,500 ms | 通过 |

分页模型生成 2,518 个临时页面定义；观测 Node 堆增长峰值为 21.56 MiB，低于 300 MiB 预算。命令会在预算断言之前输出 `READER_PERF_RESULT` 和 `READER_PERF_BUDGETS`，失败消息同时包含实际值、预算及完整结果，便于定位回归。
