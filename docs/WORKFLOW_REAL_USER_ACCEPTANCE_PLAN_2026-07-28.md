# 工作流真实作者验收与优化计划（2026-07-28）

## 1. 目标

本轮不新增大型能力，集中验证并打磨 F-09 半自动工作流，使普通作者能够在真实桌面界面、真实项目数据和真实 Provider 下完成：

1. 从零创建项目并生成可回流的作品。
2. 基于已有正文续写。
3. 对已有正文执行大段重写并选择性回流。
4. 在取消、刷新、关闭应用、生成失败、回退和重生成后继续工作。
5. 清楚理解每个 AI 配置负责的模块、当前步骤产生了什么、下一步会修改什么。

## 4. 真实验收矩阵

### A. 从零创作：`巢都之梦`

1. 重新打开应用，确认恢复后的活动节点、产物 Revision、冻结模型和事件日志不变。
2. 检查蓝图摘要、完整产物、编辑保存新 Revision、旧 Revision 可回看。
3. 确认蓝图，使用真实 Pro 生成“人物与世界观资料草稿”；开启深度思考并检查：
   - 推理气泡只在请求期间出现。
   - 推理与正文分流。
   - 完成后自动收起，可重新打开。
   - 产物在主区域可见，不依赖事件日志判断结果。
4. 修改一张人物卡后审批，验证修改形成子 Revision。
5. 真实生成节奏与场景计划；将首轮控制在 1–2 场，检查目标字数、情绪、冲突和细纲。
6. 真实生成分场正文，检查长文本流式显示、批次进度、取消按钮和超时反馈。
7. 执行 AI 语义审查，确认规则审查与模型审查结果可区分。
8. 分别执行正文回流与资料卡回流：
   - 两项都必须单独确认。
   - 正文场景保留来源 Run/Artifact/Revision。
   - 资料卡保留来源证据。
   - 重复应用不产生重复场景或资料卡。
9. 关闭并重开应用，验证项目正文、资料卡、运行状态、事件和所有 Revision 可恢复。

### B. 已有正文续写

项目：`workflow-ui-continuation-20260724`。

1. 分别验证当前场景、当前章节、整个项目三种范围显示的字符数和来源说明。
2. 真实生成原文分析，确保只总结已有内容，不越界续写。
3. 使用一条倾向锁和一条硬排除锁生成方向；检查所有方向是否遵守排除项。
4. 选择一个方向，生成场景计划与正文；检查人物状态、事实和未解线索连续。
5. 执行审查并回流写作区；再次应用不得重复追加。
6. 在独立空项目上验证续写被前端与服务层同时拒绝，且不创建孤儿 Run。

### C. 大段重写

项目：`project-1784889287553-q3nc7q` 或本轮续写产生的两场正文。

1. 冻结两场来源，真实生成重写计划。
2. 真实生成逐场重写和衔接修复。
3. 检查原文/重写版逐场比较、字符差异、事实保留和场景选择。
4. 只勾选一场回流，确认未勾选场景保持原文。
5. 验证应用前备份、版本冲突拒绝、重复提交幂等和备份恢复。

### D. 恢复、回退与失败路径

1. 在“已有待审批产物”状态取消，再恢复；原 Revision 必须保留且下一步按钮恢复。
2. 从当前步骤返回上一个节点：
   - 历史产物保留。
   - 当前及下游产物标为过期。
   - 重生成后审批使用新 Revision。
3. 生成期间取消真实请求，确认请求停止、节点可重试、不留下半成品正式产物。
4. 等待审批时刷新页面、关闭应用、重开应用，状态必须一致。
5. 使用自动化故障注入验证 401、429、首响应超时、流中断、空响应和无效 JSON；真实密钥不做破坏性修改。

### E. 视觉与可访问性

每条主流程至少覆盖：

- 1920×1080、1366×768、1280×720。
- 100%、125%、150%、200% 等效缩放。
- 键盘 Tab/Shift+Tab、Enter/Space、Escape。

检查项：

- 当前步骤、当前产物和主操作在首屏可发现。
- 不出现互相竞争的多层滚动条、遮挡、裁切或按钮落在不可见区域。
- 焦点可见且顺序合理；状态变化有可访问播报。
- 文本、禁用态和边框对比度足够；按钮目标不小于常用桌面可点击尺寸。
- 中文状态一致，不混用 `approved`、`waiting_review`、`blueprint` 等内部值。

## 5. 当前已发现问题

1. 书库已过滤 `backups`、`.removed-projects` 和隐藏保留目录，并增加存储层回归测试。

7. 真实窗口复查确认完整产物区不会被当前结果遮挡，书库不再出现伪项目。

### P0：必须先保证数据与闭环正确

1. 尚未在修复后的真实 UI 中重新跑完“恢复后的从零创作 → 正文/资料回流 → 重开恢复”。
2. 尚未对修复后的续写与重写执行完整真实 Provider 闭环。
3. 取消真实流、刷新/重开、版本冲突和重复应用仍需组合验证。

### P1：明显阻碍作者操作

1. 结构化摘要已经可读，但复杂产物仍缺少逐字段表单编辑器；当前修改入口仍是高级 JSON 编辑。
2. 真实 Provider 长正文生成时的批次进度、耗时和费用摘要仍需在后续真实闭环中继续打磨。

### P2：一致性与可访问性

1. 辅助文本字号已提高，但 125%–200% 缩放、键盘焦点和低亮度主题仍需专项回归。
2. 缺少面向作者的调用耗时、token/费用摘要和批次进度历史。

## 6. 开发顺序

### 阶段 1：完成真实闭环并只修 P0

- 按 A、B、C 三条路径运行真实 API。
- 每发现一个阻断问题，先写最小复现和回归测试，再修复。
- 不在 P0 未清零时重做整体视觉。

退出条件：

- 三类工作流均可从真实 UI 完成并重开恢复。
- 取消/恢复、回退/重生成、回流/幂等、备份/恢复全部有证据。
- 无密钥、路径或跨项目正文泄漏。

### 阶段 2：重排工作流页面的信息层级

- 将“当前运行”和“新建另一条流程”拆成明确模式；默认聚焦当前运行。
- 当前步骤采用单一、固定可见的操作区；消除嵌套滚动竞争。
- 待审批状态只保留一个主按钮“确认并进入下一步”，把重生成、回退、取消放入次级区。
- 为方向、蓝图、人物卡、场景计划、审查和重写差异提供结构化视图；原始 JSON 只作为高级编辑入口。
- 事件日志折叠为“诊断详情”。

退出条件：

- 1366×768 和 1280×720 首屏能看到当前结果与下一步。
- 普通作者无需理解内部节点 ID、Review State 或 JSON schema。

### 阶段 3：书库、状态文案与可访问性

- 过滤保留目录和无效项目目录。
- 统一全部运行、节点、产物和事件的中文状态。
- 完成键盘、焦点、状态播报、对比度和 200% 缩放回归。
- 增加真实调用的耗时、token 和费用摘要，但不暴露请求正文或密钥。
