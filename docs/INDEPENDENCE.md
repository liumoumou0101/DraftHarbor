# 稿湾独立化说明

最后更新：2026-07-11

## 结论

稿湾是从 Writingway 2 Fork 的长期重构中演变出来的独立桌面产品。新仓库不继承原 Git 历史，不包含旧网页运行时、原品牌资源、原 Python 服务、跟踪的依赖目录、项目备份、Agent 日志或开发过程截图。

“独立”描述的是当前产品、品牌、仓库和维护边界，并不否认项目起源。来源和致谢始终保留在 README 与 NOTICE 中。

## 已移除的继承内容

- `main.html` 和旧 Alpine 应用主体 `src/app.js`
- 旧 `src/modules/`、IndexedDB 页面逻辑和浏览器生成适配层
- 原 Logo、favicon 和来源不清的桌面图标
- Python 应用服务、更新器和 llama.cpp 安装逻辑
- GitHub Gist 备份旧实现
- 旧网页测试和依赖旧模块的测试
- 原项目说明、备份文档、日志、目录快照和历史副本
- 跟踪进仓库的 `node_modules`、项目备份和本机数据

## 保留的兼容能力

- 导入 Writingway 1 文件夹数据
- 导入旧 Writingway 2 JSON snapshot
- 识别旧章节、场景、资料和 Prompt 字段

这些能力由稿湾服务层解析数据格式，不需要加载或运行旧网页应用。

## 定点重写

独立化迁移中重新实现了 Prompt 构建器和 Provider 流式解析器。它们继续满足稿湾既有测试契约，但采用新的数据组织、模板组装、SSE 解析和请求构建方式。

EPUB 中的 mimetype、container.xml、OPF 和 NCX 字段属于公开标准所要求的固定结构，不视为特定项目独有表达。

## 仓库边界

正式仓库只保留：

- Electron 桌面主线
- 服务层、存储层和纯核心层
- 自动化测试
- 用户、架构、许可和贡献文档
- 新的 DraftHarbor 品牌资源

内部 Agent 日志、阶段任务书、视觉审计过程图、安装包和真实项目数据不进入正式仓库。
