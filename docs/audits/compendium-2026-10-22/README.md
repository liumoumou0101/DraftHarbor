## 界面问题与改法

| 优先级 | 观察与证据 | 对使用的影响 | 建议 |
| --- | --- | --- | --- |
| 高 | 01、02：标题、摘要、正文和八个人物字段连续排列为表单 | 查看资料时缺少清晰的内容层次，编辑控件始终占据注意力 | 改为可直接编辑的档案页；稳定标题区；正文与人物字段分区 |
| 高 | 02、03：语气、当前状态、已知信息、关系备注都是单行输入框 | 长内容难以完整阅读，编辑时需要在输入框内移动 | 长字段使用多行自适应编辑，阅读时自然换行；按动机、状态、关系分组 |
| 高 | 01、03：标签、别名及 AI 注入策略藏在同一个底部折叠区 | 找卡、认识人物和控制 AI 使用三个不同任务混在一起 | 标签、别名靠近标题；AI 使用单独设置区，直接显示当前模式 |
| 高 | 03：同时存在“总是加入生成上下文”复选框和“模式：总是注入”下拉框 | 同一意图出现两套入口，用户难以建立稳定理解 | UI 只保留一套明确的 AI 使用模式；兼容字段由数据层处理 |
| 中 | 01、02：深色整体中嵌入大块浅色正文编辑框 | 正文与其他字段的视觉语言不一致，表单感更强 | 统一正文、资料属性和面板的主题色阶，保留明确的焦点样式 |
| 中 | 01、02：筛选、创建和“更多”占据列表顶部；列表重复展示类型与策略徽标 | 类型、内容和状态的视觉主次不够清晰 | 提供紧凑列表：名称为主、一行摘要为辅；类型筛选稳定，策略状态适度弱化 |
| 中 | 01：详情缺少来源及被使用位置，页面只展示资料本身 | 无法从资料直接确认哪个章节引用、从哪里提取 | 规划“引用与来源”区；写作、阅读、讨论和工作流共享资料预览抽屉 |
| 中 | 01：删除与 AI 重写、保存位于日常主操作区 | 高频编辑操作与低频危险操作并列 | 保存状态与主操作固定；删除放入更多菜单，继续保留确认 |

1280 × 720 下部分字段需要滚动，这本身不属于内容丢失。问题在于重要设置的发现成本；没有据截图声称存在不可滚动的溢出。颜色对比尚未做量化无障碍验收。

## 推荐的重写范围

采用 Novelcrafter 的信息组织方式与 Capacities 的内容排版，保留稿湾现有主题体系。

1. **左侧资料目录**：搜索、类型筛选、紧凑列表，支持清楚的空状态和无结果状态。
2. **中央资料档案**：名称、类型、别名和标签形成标题区；正文可直接编辑；人物长字段自然换行，按语义分组。
3. **详情分区**：正文、人物信息、引用与来源。AI 使用策略独立呈现，显示常驻、自动、提及、手动或禁用的实际状态。
4. **跨模块预览抽屉**：写作、阅读、讨论和工作流点击同一资料时共享展示；在窄窗口中按需打开，避免强塞常驻三栏。
5. **保留可靠编辑行为**：未保存提示、冲突保护、保存失败保留草稿、AI 建议逐项审核继续作为基础能力。

第一阶段重写目录与详情的视觉及交互，不需要改变现有资料格式。来源、关联章节和人物关系属于后续产品能力，需要先确定并补齐数据契约，不能仅靠摆出空面板表达已经实现。

## 已修复的行为

| 范围 | 本轮结果 |
| --- | --- |
| 工作流 → 资料库 | 提交原始预览，冻结目标、版本和补丁；显式 ID 优先、同类型匹配、拒绝歧义；应用前拒绝同批重复资料目标 |
| 阅读 → 资料库 | 抽取时记录候选目标版本，包括疑似重复的手选目标；提交使用项目锁和最终版本检查 |
| 写入与恢复 | 工作流应用、恢复使用项目锁；写入前和恢复待执行操作前校验；新建要求目标不存在 |
| 资料管家与编辑 | 严格核对建议 ID、审核关联和可见操作；窗口关闭保护未保存资料和正在写入状态；空 AI 结果保留原草稿；提取保留别名；参考超限撤销本次选择 |
| 写作、讨论、工作流 | 摘要及八个人物字段贯穿上下文；当前场景人物与 POV 进入匹配；手动和常驻资料优先保留；预览与生成使用相同选择；修改写作要求立即刷新引用预览 |
| 资料检索与问答 | 本地与服务检索覆盖人物字段；长正文截取命中附近证据并保留原文偏移；没有有效引用时不提供缺少依据的答案 |
