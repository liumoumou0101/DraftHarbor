# F-09.4 工作流画布视觉审计

- 日期：2026-07-15
- 环境：真实桌面壳、本地隔离项目、重写引导运行，Codex 内置浏览器 1260 × 720
- 健康度：通过（修正后无阻断级布局或交互问题）

## 审计路径

1. 从书库打开“潮汐城档案”，进入工作流并切换图视图。
2. 检查只读运行态的节点、连线、活动节点、执行操作和横向导航。
3. 从运行快照创建编辑草稿，检查节点库、端口、配置面板和画布可用空间。
4. 建立产物类型不兼容的连线，检查校验门禁和错误反馈。
5. 修正编辑布局、端口点击区域与错误文案后，按同一路径重新取证。

## 结论与修正

- 已修正：编辑态原先把 842px 主内容区拆成画布与 250px 侧栏，导致节点库、表单和画布同时横向裁切。配置面板现移到全宽画布下方，画布和面板实测宽度均为 842px。
- 已修正：节点端口原先只有约 8px 字号和极小点击面；现为 9px 字号、22px 最小点击高度，并同步增加节点高度，降低误触。
- 已修正：类型校验原先直接显示 `artifact types are incompatible`；现显示“产物类型不兼容”，并使用 `role="alert"` 通知辅助技术。
- 保留：长工作流仍以横向画布承载，横向滚动是信息架构的一部分；修正重点是避免配置面板进一步压缩画布。

## 正向观察

- 只读态与编辑态区分清楚，编辑必须先创建独立草稿，符合运行快照不可变的心智模型。
- 活动节点、完成状态、能力 ID 和产物数量在同一张节点卡上可见，执行上下文完整。
- 无效连线会留在草稿中供用户定位，同时阻止完成编辑或保存模板，不会污染真实运行。

## 可访问性与证据边界

- 已验证端口点击区域、错误提示语义和键盘可聚焦的原生按钮/表单控件。
- 本轮没有独立屏幕阅读器与高对比度模式测试。
- 内置浏览器当前只提供固定 1260 × 720 视口；未对更小窗口和高 DPI 做独立截图，相关响应式 CSS 仍由自动化与后续桌面回归覆盖。
