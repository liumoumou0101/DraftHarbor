# F-10 阅读器发现审计

- 日期：2026-07-15
- 环境：真实桌面壳、9 章项目样本、1260 × 720 内置浏览器
- 总体健康度：基础功能可用，但仍是文本预览器，不具备沉浸式电子书体验和创作转交能力

## 步骤

1. **从书库打开项目并进入阅读页——可用。** 当前项目可自动聚合为章节，标题、正文、上一章/下一章和阅读进度均正常显示。
2. **检查默认深色阅读态——需重构。** 正文清楚，但永久侧栏同时承载导入、排版、进度和目录，占用约四分之一主宽；没有页边界、分页或双页心智。
3. **切换纸张主题与衬线字体——部分可用。** 主题确实应用到正文区域，但应用外壳和左侧设置区保持深色，整体更像“浅色文档嵌在工具中”，不是完整阅读环境。
4. **切换章节并验证进度——可用但不准确。** 章节切换与位置恢复有效；全书百分比按章节等权计算，长短章混合时会失真。

## 正向观察

- 当前项目与外部文档已共用同一阅读渲染入口，后续可以在此基础上升级 Reader Document。
- 排版设置使用原生表单控件，主题、字号、行距和版心均可即时调整。
- 正文使用真实文本节点而非画布，文本选择、辅助技术和 AI 选区转交具备良好基础。

## 主要风险

- 结构风险：阅读 chrome 永久可见、目录位于设置区下方，长目录的发现和切换成本高。
- 心智风险：“Local Reader”同时显示项目正文，无法表达当前来源、是否可编辑以及转交目标。
- 数据风险：外部全文进入 localStorage，只有单本文档状态；缺少稳定文档 ID、来源摘要和跨模块 locator。
- 可访问性风险：滑杆没有当前数值文本；未来翻页动画必须提供无动画/减少动态效果；双页只能改变视觉布局，DOM 阅读顺序必须保持连续。

## 证据限制

- 本轮只对桌面 1260 × 720 视口、项目阅读和现有主题切换取证。
- 外部文件导入功能已有自动化覆盖，但内置浏览器本轮无法直接驱动文件选择器，因此没有把导入状态作为视觉证据。
- 未执行屏幕阅读器、高对比度、触控、窄窗口和高 DPI 测试。
