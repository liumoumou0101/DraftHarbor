## 验收结论

- 批次：6。
- 正文场景：25。

- 模型调用：44 次；网络或服务调用失败 0 次。
- 因输出长度截断触发 JSON 修复：2 次，均自动修复成功。
- 五次批间修改意见均成功写入下一批规划上下文。
- 工作流最终状态为 `completed`，25 个场景全部转入写作区。

功能链路已经具备真实可用性，但正文离“无需人工处理即可发布”仍有明显距离。较准确的定位是：能够快速生成结构完整、主题稳定的长篇初稿，之后仍需结构编辑和语言精修。

## 正文质量评价

### 做得较好的部分

1. **不是只生成开头。** 故事完成了起因、调查、交易、联盟、红月冲突和旧契约终结，结尾有明确余波，不再是早期工作流只能产出数个场景的“大章开头”。
2. **主题锚定稳定。** “名字、记忆、契约、饥饿”贯穿六批，没有在长篇生成中换题材。统计中“名字/姓名”出现 561 次，“契约/约定”出现 370 次。
3. **主角主动性较好。** 小红帽从被动承受转为主动交易、谈判、改写规则，满足了 Brief 中最重要的角色弧要求。
4. **黑童话意象有辨识度。** 红斗篷被设计为活的契约器官，狼群保留非人类的交流方式和政治关系，外婆、母亲与守门人制度形成了较完整的代际因果链。
5. **批间意见确实生效。** 后续批次能响应“提高主动性、兑现名字交换、开始收束伏笔”等调整，并非形式上保存意见但不进入提示词。

### 需要优先修改的部分

1. **场景边界越界并造成重复。** 第 4 批第一场已经完成老狼王谈判并以“成”收束，下一场却从同一谈判开头重新生成。这是本次唯一被批次审查标为 `error` 的问题。
2. **创作过程标签泄漏到正文。** 后段出现 11 处“在场景 6-1 中”“场景 5-2”等内部定位文字，破坏小说沉浸感。
3. **文体后期技术说明化。** 抽查统计到至少 46 处明显的“赫兹、神经、动脉、海马体、精确温度或生理参数”等技术语体。它们让原本有效的黑童话感逐渐变成机制说明。
4. **对话不足。** 实际对话字符比例约 17.32%，低于全局写作要求中的 25%–35%。大量调查和机制揭示依靠旁白完成，次要角色的声音不够充分。
5. **伏笔有未闭合项。** 欠名契约上的幼狼爪痕被明确强调，后文只提出可能与裂爪或其他附庸狼群有关，没有完成身份确认。
6. **解释性句式重复。** “不是……是……”结构使用非常频繁；“不是比喻”原句出现 7 次。单独看有效，长篇累积后会形成明显模型腔。
7. **章节组织仍偏工程化。** 写作区按“第 1 批”到“第 6 批”建立章节，适合验收但不适合读者。下一阶段应让工作流根据叙事单元形成真实卷/章，而不是暴露生成批次。
8. **首场长度不足。** 第一场仅 2,554 字符。真实运行由此发现旧提示词没有明确 `targetWords` 是中文字符目标；运行中修正后，后续场景长度明显改善。
9. **逐场生成时标题曾被通用标题覆盖。** 原转写结果的 25 个场景都显示为“分场正文”，难以浏览。测试项目已按原场景计划恢复 25 个真实标题，正文内容未修改。

综合人工抽查建议评分为 **7/10 左右的长篇初稿**。DeepSeek 总编评审给出 8/10，方向基本可信，但偏乐观，并漏掉了创作标签泄漏与技术说明化的严重程度。

## 本次随验收完成的修复

1. 正文提示词明确 `currentScene.targetWords` 为中文字符目标，并要求非自然结束时不低于目标的 80%。
2. 正文提示词增加严格场景边界：不得提前写完下一场景核心转折；若前场已越界，必须从最新事实推进而非重演。
3. 正文提示词禁止把场景 ID、批次、计划要求等内部过程信息写入正文。
4. 工作流向空白新项目首次转入正文后，自动把当前场景切换到首个生成场景，避免用户打开项目仍看到空白页。
5. 审查严重度统计补充识别 `error/错误`，本次重大问题数从错误的 0 修正为 1。
6. 长 JSON 输出不再依赖固定 5,000 tokens；本次真实运行验证了长度截断后的自动 JSON 修复链路。
7. 逐场、单输出的生成结果也会采用调用方传入的真实场景标题，不再因为每次只保存一个场景而退回通用“分场正文”。

## 下一轮建议

1. 在每个场景生成后增加“边界重叠检查”，对前场结尾与本场开头做语义去重；仅靠提示词不能完全保证。
2. 增加正文清洁检查，拦截“场景 6-1、批次、JSON、fineOutline”等过程标签，并允许一键重写受污染段落。
3. 将批次规划与读者章节拆开：批次是生成单位，章是叙事单位，转写时由章节装配器重新分章。
4. 对全局文风限制增加可检测规则，例如技术词密度、解释性旁白、重复句式和目标对话比例，并把结果显示在批次复核界面。
5. 压缩滚动上下文：优先传递结构化连续性状态、最近正文和未闭合线索，避免每个场景都携带过多历史文本。
6. 为“重大审查问题”设置阻断或显式确认；本次虽然发现谈判重复，自动运行仍继续到了终局。
